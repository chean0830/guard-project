# 전/월세 사기 방지 프로그램 기획서

## 1. 서비스 소개

**한 줄 소개**
전세나 월세 계약을 하기 전에, 등기부등본이라는 서류를 올리면 이 집에 위험한 점은 없는지 자동으로 확인해주고, 쉬운 말로 알려주는 서비스.

**왜 필요한가**
등기부등본에는 이 집에 빚이 얼마나 있는지, 소유자가 누구인지 같은 정보가 담겨 있다. 하지만 처음 보는 사람은 용어가 어려워서 뭐가 위험한 건지 알기 힘들다. 이 서비스는 그 어려운 서류를 대신 읽어주고, "여기를 확인해보세요"라고 짚어주는 역할을 한다.

**대상 사용자**
처음으로 전세나 월세 계약을 하는 사회초년생, 자취를 시작하는 대학생 등 계약서에 도장 찍기 전에 확인이 필요한 모든 사람.

## 2. 기능 목록 (우선순위별)

### P0 — 반드시 있어야 서비스가 성립하는 기능 (1차 목표)

| 기능 | 설명 |
|---|---|
| 서류 올리기 | 등기부등본 PDF 파일 업로드 + 카메라 촬영 업로드 |
| 입력 폼 | 주소, 보증금, 계약 형태 입력 |
| 서류 자동 읽기 | PDF/촬영 이미지에서 빚, 압류, 소유권 정보 추출 |
| 시세 비교 | 정부 공개 실거래가와 비교 |
| 위험 신호 카드 | 분석 결과를 카드 형태로 보여주기 (근거 포함) |
| 체크리스트 | 서류만으로 알 수 없는 항목을 할 일 목록으로 안내 |
| 결과 리포트 화면 | 전체 결과를 한 화면에 정리 |

### P1 — 있으면 서비스 완성도가 크게 올라가는 기능 (2차 목표)

| 기능 | 설명 |
|---|---|
| 경매 배당 시뮬레이터 | 낙찰가를 조절하며 보증금 회수 가능액 확인 |
| 원본 서류 근거 하이라이트 | 분석 결과와 원본 PDF 위치를 나란히 보여줌 |
| 권리 관계 타임라인 | 소유권 변동, 근저당 설정 등을 시간순으로 표시 |
| 분석 진행 상황 표시 | 분석 중 단계별 진행률 실시간 표시 |

### P2 — 여유가 있을 때 (3차 목표)

| 기능 | 설명 |
|---|---|
| 결과 리포트 공유 | 링크나 PDF로 리포트 저장/공유 |
| 로그인 및 이력 저장 | 분석 이력 관리 |
| 쉬운 설명 (LLM) | 위험 신호를 자연어로 풀어서 설명 |

### 대상 부동산 유형

| 유형 | 지원 여부 | 비고 |
|---|---|---|
| 아파트 | 지원 | 1차 개발/검증 대상 |
| 오피스텔 | 지원 | 등기부 형식(집합건물) 동일, 실거래가 API만 별도 신청 |
| 빌라(연립·다세대) | 지원 | 등기부 형식(집합건물) 동일, 실거래가 API만 별도 신청 |
| 원룸·다가구주택 | 조건부 지원 | 호실별 등기부가 없어 먼저 들어온 세입자 보증금·건물 시세를 사용자가 직접 입력. 입력값에만 의존하므로 "안전" 판정을 내리지 않음 (결정사항 44번) |

### 이번에는 하지 않는 것 (범위 밖)

- 다가구주택 선순위 보증금·건물 시세 자동 조회 (공식 서류를 API로 받을 수 없음, 결정사항 44번)
- "안전/위험"을 법적으로 확정해서 알려주는 것 (참고 정보만 제공)
- 등기부등본 자동 발급/조회 (사용자가 직접 업로드)

> 촬영 이미지 OCR 지원 여부 및 우선순위는 `결정사항.md` 참고 (원 기획서에서는 OCR 불필요로 명시했으나 이후 변경됨)

## 3. 사용자 흐름

1. 계약하려는 집 주소와 보증금 금액 입력
2. 등기부등본 파일 업로드 (파일 업로드 또는 카메라 촬영)
3. 분석 진행 (서류 읽기 → 시세 조회 → 건축물 정보 조회 → 위험 판단)
4. 결과 화면에서 위험 카드 확인
5. (선택) 시뮬레이터로 여러 상황 가정
6. 체크리스트 확인 후 집주인에게 요청할 항목 정리

## 5. 기술 구성

- **웹 화면**: Next.js — 브라우저에서 접속하는 화면
- **앱 화면**: Flutter — iOS/Android 공통 앱 (개발 순서상 최후순위, `결정사항.md` 참고)
- **서버**: Spring (Java) — 서류 분석, 위험 판단, 시세 비교를 처리하는 핵심 두뇌
- **OCR**: Google Cloud Vision API — 카메라 촬영 이미지에서 텍스트 추출
- **원칙**: 웹과 앱은 화면만 다르고, 실제 분석 로직은 전부 Spring 서버 한 곳에서 처리한다. 규칙이 바뀌면 서버만 수정하면 웹/앱에 동시에 반영된다.

```
[Next.js 웹]   [Flutter 앱]
      \             /
       \           /
      [Spring 서버] — 서류 분석, 위험 판단, 시세 비교, OCR 연동
            |
     [데이터베이스] — 판단 규칙, 분석 결과 저장
            |
   [정부 공개 API / Google Vision API] — 실거래가, 건축물대장 조회, OCR
```

## 6. 서버(Spring)가 하는 일

1. 파일 받기 — 업로드된 등기부등본 파일(PDF) 또는 촬영 이미지 수신
2. 서류 읽기 — PDF는 텍스트 직접 추출, 이미지는 Google Vision OCR로 텍스트 추출 후 빚·압류 등 정보 파싱
3. 정부 정보 조회 — 실거래가, 건물 정보 가져오기
4. 위험 판단 — 기준표와 비교해 위험 요소 판별
5. 결과 전달 — 웹/앱에 동일한 형식으로 응답

## 7. 개발자가 기본적으로 지켜야 하는 것 (보안/개인정보)

이 서비스는 등기부등본이라는 민감한 개인정보(소유자 이름, 주소, 채무 정보)를 다루기 때문에 아래 항목은 선택이 아니라 **필수**로 지켜야 한다.

### 파일/데이터 처리

- [ ] **업로드 파일 비저장 원칙**: 등기부등본 원본(파일/촬영 이미지)은 분석이 끝나면 즉시 삭제한다. 디스크에 남기지 않고 메모리에서만 처리하는 것이 이상적이다.
- [ ] **파일 저장이 불가피하다면**: 저장 즉시 암호화하고, 일정 시간이 지나면 자동 삭제되는 정책(TTL)을 둔다.
- [ ] **로그에 개인정보 남기지 않기**: 에러 로그, 접근 로그에 파일 내용이나 개인정보가 그대로 찍히지 않도록 마스킹한다.
- [ ] **OCR 연동 시 외부 전송 최소화**: Google Vision API로 이미지를 전송할 때도 분석 후 원본을 서버/외부에 남기지 않는다.

### 통신 보안

- [ ] **HTTPS 필수**: 웹, 앱, 서버 간 모든 통신은 HTTPS(TLS)로 암호화한다. 평문 HTTP는 사용하지 않는다.
- [ ] **API 요청 검증**: 서버로 들어오는 모든 입력값은 형식과 크기를 검증한다 (파일 크기 제한, 확장자 검사 등).

### 인증/인가

- [ ] **비밀번호는 절대 평문 저장 금지**: 로그인 기능을 넣는다면 bcrypt 같은 단방향 해시 알고리즘으로 저장한다.
- [ ] **API 키, 비밀 정보는 코드에 하드코딩 금지**: 환경 변수나 별도 설정 파일(.env)로 분리하고, `.gitignore`에 등록해 저장소에 올라가지 않게 한다.
- [ ] **인증 토큰 관리**: 로그인 기능이 있다면 JWT 등의 토큰 만료 시간을 짧게 설정하고, 갱신(refresh) 로직을 둔다.

### 데이터베이스 보안

- [ ] **SQL 인젝션 방지**: 쿼리를 문자열로 직접 조합하지 않고, JPA/MyBatis 같은 ORM이나 PreparedStatement를 사용한다.
- [ ] **민감 정보 암호화 저장**: 혹시 개인정보를 저장해야 한다면(이름, 주소 등) DB 컬럼 단위로 암호화한다.
- [ ] **접근 권한 최소화**: DB 계정에 필요한 권한만 부여한다 (분석 서버가 DB 삭제 권한까지 가질 필요는 없다).

### 웹/앱 공통 보안

- [ ] **CORS 설정**: 허용된 도메인에서만 API를 호출할 수 있도록 제한한다.
- [ ] **CSRF, XSS 방어**: 입력값을 그대로 화면에 출력하지 않고 이스케이프 처리한다.
- [ ] **의존성 라이브러리 관리**: 사용하는 오픈소스 라이브러리의 알려진 보안 취약점을 주기적으로 확인한다.

### 법적/윤리적 고지

- [ ] **면책 문구 명시**: "이 서비스는 법률 조언이 아니며 참고용 정보"라는 안내를 결과 화면에 반드시 표시한다.
- [ ] **이용 제한 문구 명시**: "본인이 계약 당사자이거나 본인 명의로 열람 가능한 부동산에 한해 사용하세요" 등 오남용 방지 안내를 업로드 화면에 표시한다.
- [ ] **개인정보처리방침 작성**: 실제 배포 시에는 어떤 정보를 어떻게 처리하는지 명시한 페이지를 둔다.

> 포트폴리오 관점에서도 이 항목들은 중요하다. "왜 파일을 저장하지 않았는지", "왜 HTTPS를 썼는지"를 면접에서 설명할 수 있으면 개인정보를 다루는 서비스를 만들 때의 기본기를 갖췄다는 신호가 된다.

## 10. 개발 순서 (대략적인 흐름)

1. **공공데이터 API 승인 신청** (승인 대기 시간이 있어 최우선 진행)
2. **서버 핵심 기능**: 서류 읽기(PDF 텍스트 추출 + OCR), 위험 판단 규칙 만들기 (P0)
3. **웹 화면**: Next.js로 입력, 결과, 상세 화면 (P0)
4. **보안 기본기 적용**: 위 7번 체크리스트를 개발 초기부터 함께 적용 (전 구간)
5. **P1 기능 추가**: 시뮬레이터, 원본 서류 보기, 타임라인
6. **앱 화면**: Flutter로 동일 화면 구성, 같은 서버 사용 (최후순위)
7. **마무리**: 테스트, 배포, README 작성
